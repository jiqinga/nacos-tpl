# 开发与贡献 🤝

欢迎贡献代码！本页说明本地开发、编码规范、提交流程与 PR 要求。所有文档、提交信息与终端文案需保持中文与贴切 emoji。🈶️

## 本地开发
- 构建：`cargo build` / `cargo build --release`
- 运行：`cargo run -- <subcommand> ...`
- 测试：`cargo test --workspace --all-features`
- 格式：`cargo fmt --all -- --check`
- 静态检查：`cargo clippy --all-targets --all-features -- -D warnings`

## 代码结构
- `src/`：核心源码（`main.rs`、`render.rs`、`apply.rs`、`init.rs`、`validate.rs`、`diff.rs`、`cfg.rs`、`nacos.rs` 等）。
- `tests/`：集成测试（可添加替身/假实现，避免真实网络）。
- `config/`：默认配置模板（不得提交敏感信息）。
- `scripts/`：脚本与本地引导工具。
- `docs/wiki/`：Wiki 草稿（可复制到 GitHub Wiki 仓库）。

## 编码规范
- Rustfmt（4 空格），提交前必须通过 `fmt` 与 `clippy`。
- 命名：函数/模块 `snake_case`，类型/trait `UpperCamelCase`，常量 `SCREAMING_SNAKE_CASE`。
- 公共 API 编写 rustdoc；模块尽量小且显式 `pub`。
- 错误文案：中文 + 合适 emoji（如：⚠️、🐛、🚫、✅、🔍、🚀 等）。

## 提交流程
- 提交信息：遵循 Conventional Commits（如 `feat: ...`、`fix: ...`、`chore: ...`），祈使句，范围明确。
- 分支命名：`feat/<topic>`、`fix/<topic>`、`chore/<topic>`。
- PR 说明：问题背景、变更摘要、本地验证步骤；关联 Issue；确保 `fmt`、`clippy`、`test` 全部通过。

## 测试建议
- 单元测试：与源码同文件夹内，`#[cfg(test)]` 模块。
- 集成测试：`tests/`（如 `tests/config_load.rs`、`tests/nacos_client.rs`）。
- 慢测/外部依赖：使用 `#[ignore]`；e2e 建议以特性门控（`--features e2e`）。

## 发布说明
- 使用 GitHub Actions 自动构建与发布，详见 “CI 与发布”。
- 建议在打标签前更新 CHANGELOG 或在 Release 说明中补充变更摘要。📜
