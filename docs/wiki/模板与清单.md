# 模板与清单 🧩

**Tera 模板与兼容变量语法**
- 模板引擎：Tera（`{{ }}`/`{% %}` 等）。
- 兼容变量：`${VAR}`、`${ VAR }`、`${VAR:-default}`、`${ VAR : - default }`。
- 转义规则：`$${VAR}` → `${VAR}`（避免误替换）。
- 缺失变量：默认报错退出；若传 `--allow-missing`，将保留占位符。⚠️

**front-matter（可选）**
- 文件开头使用 YAML front‑matter 标记 `dataId/group`：
```yaml
---
dataId: app.yaml
group: DEFAULT_GROUP
---
后续为模板正文...
```
- 用途：当没有 `manifest.yaml` 时，`--print-id` 会回退到扫描 front‑matter。🧭

**manifest.yaml（渲染/选择辅助）**
- 生成方式：目录渲染时加 `--write-manifest`，或使用库函数 `write_manifest_output`。📄
- 结构（例）：
```yaml
items:
  - path: DEFAULT_GROUP/app.yaml
    dataId: app.yaml
    group: DEFAULT_GROUP
    type: yaml
    tenant: public
```
- 作用：
  - `render --print-id`：按 dataId/group 选择相对路径。
  - 生成/导入环节中作为“索引”与“可读性清单”。

**.metadata.yml（上传/对比白名单）**
- 位置：渲染输出目录根（如 `build/dev/.metadata.yml`）。
- 作用：若存在则仅处理列出的条目（白名单）；始终跳过 `.metadata.yml/.yaml` 与 `manifest.yaml`。🚫
- 示例：
```yaml
metadata:
  - dataId: application.yml
    group: DEFAULT_GROUP
    type: yaml
  - dataId: kafka.properties
    group: DEFAULT_GROUP
```

**group/dataId 的推导规则**
- 从路径 `<root>/<GROUP>/<DATAID>` 推导；不足两级时默认 `group=DEFAULT_GROUP`。🧮

**变量展开的扁平化规则**
- YAML 层级 `a.b.c` → `A_B_C`；数组保留为 JSON 字符串。
- 环境变量（大写）覆盖同名键。🔧
