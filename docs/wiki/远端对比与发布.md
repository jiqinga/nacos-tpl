# 远端对比与发布 🔍🚀

本页介绍如何使用 `diff-remote` 对比本地与远端，以及使用 `apply` 并发发布配置到 Nacos（带重试、超时、覆盖与命名空间管理）。

## 对比远端（diff-remote）
- 目标：判断每个 `(group, dataId)` 的文本是否一致，统计 same/changed/added，并可输出差异。
- 来源：本地目录通常是 `render` 输出目录，或你手工组织的 `<GROUP>/<DATAID>` 结构。
- 白名单：若目录包含 `.metadata.yml`，仅处理其中列出的条目（同时跳过 `.metadata.yml/.yaml` 与 `manifest.yaml`）。

示例：
```bash
nacos-tpl diff-remote -s 127.0.0.1:8848 -n public -d build/dev \
  --only-changed --diff-style side-by-side --context 5
```

关键参数：
- `-s, --server <url[,url]>`：多个地址逗号分隔；缺协议自动补全为 `http://`。
- `-n, --namespace <tenant>`：命名空间；未提供会尝试从 `.metadata.yml` 推断。
- `-d, --dir <path>`：本地目录。
- `--include/--exclude <glob,glob>`：相对目录的 glob 过滤。
- `--only-changed` / `--only-added`：过滤输出类型。
- `--diff-style <unified|side-by-side>` 与 `--context <n>`：差异风格与上下文行数。
- `--json` / `--report <path>`：JSON 输出与写文件。

## 发布配置（apply）
- 目标：将本地渲染结果发布到 Nacos；默认不覆盖已存在配置，支持空跑。
- 并发：使用线程池并发发布，`--concurrency` 控制并发度。
- 重试：指数退避（200ms 起，翻倍增长），`--retries` 控制重试次数。
- 超时：`--timeout-ms` 设置 HTTP 客户端超时。
- 令牌：优先使用配置 `token`；若未提供则按 `-u/-p` 轮询登录获取并附加至请求。🔑
- 命名空间：发布前可选择 `--create-namespace` 自动创建（禁止为 `public`）。
- 跳过与覆盖：`--skip-unchanged` 一致即跳过；`--overwrite` 明确允许覆盖已存在配置。

示例：
```bash
nacos-tpl apply -s http://127.0.0.1:8848 -n public -d build/dev \
  --skip-unchanged --retries 3 --concurrency 5 --timeout-ms 10000 \
  --normalize-lf --max-bytes 1048576 \
  --json --report dist/apply-report.json --report-mode overwrite --fail-on-error
```

关键参数：
- `-s, --server` / `-n, --namespace` / `-d, --dir`。
- `-u, --username` / `-p, --password`，或配置文件内的 `token`。
- `--concurrency <N>` / `--retries <N>` / `--timeout-ms <ms>`。
- `--dry-run` / `--skip-unchanged` / `--overwrite` / `--create-namespace`。
- `--normalize-lf` / `--max-bytes <N>` / `--include-md5`。
- `--json` / `--report <path>` / `--report-mode <overwrite|append|timestamp>` / `--fail-on-error`。

报告输出（JSON）字段：
- `updated/skipped/failed`：数量汇总。
- `items[]`：逐项状态与原因（失败/空跑等），可包含 `localMd5/sizeBytes`。
- `groups[]`：按 group 汇总统计。

## 常见策略建议 💡
- 首次发布建议开启 `--dry-run`，确保与远端差异在可控范围内。
- 大批量发布时可适当提高 `--concurrency`，同时注意 Nacos 的 QPS 限制与网络稳定性。
- 跨环境迁移建议配合 `diff-remote --only-added/--only-changed` 先做观察，再 `apply`。
- 若远端内容使用 CRLF，可使用 `--normalize-lf` 统一换行以降低误差异。
