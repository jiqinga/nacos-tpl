# 模板语法与变量 YAML 📚

> 本页汇总 nacos-tpl 支持的模板语法（Tera + 兼容占位）以及变量 YAML 的完整写法与合并优先级。保持简洁可用，示例可直接拷贝试用。✅

## 总览
- 引擎：使用 `Tera 1.19` 渲染，未注册自定义函数/过滤器，默认不自动转义。🧩
- 占位：在 Tera 渲染后，会再次处理兼容占位 `${VAR}` / `${VAR:-default}`，支持空白。🔁
- 变量：从 YAML 扁平化为 `UPPER_SNAKE_CASE` 字符串；数组/对象会被序列化为 JSON 字符串；`null` 变为空串。🧰
- 覆盖：后加载的变量覆盖先加载的，最后由“环境变量”对已存在同名键进行覆盖（只覆盖，不新增）。🧱➡️🧱

---

## Tera 语法精要（含示例）
- 插值：`{{ APP_NAME }}`；拼接：`{{ "http://" ~ HOST ~ ":" ~ PORT }}`
- 过滤器（常用）：
  - 大小写：`{{ APP_ENV | upper }}`、`{{ APP_ENV | lower }}`
  - 替换：`{{ URL | replace(from="http://", to="https://") }}`
  - 去空白与长度：`{{ NAME | trim }}`、`{{ LIST | length }}`
  - JSON 编码：`{{ VALUE | json_encode }}`（搭配 YAML/JSON 内容时很有用）
- 条件：
  ```tera
  {% if APP_ENV == "prod" %}
  mode: production
  {% elif APP_ENV == "staging" %}
  mode: staging
  {% else %}
  mode: dev
  {% endif %}
  ```
- 循环：
  ```tera
  # 逗号分隔字符串 -> 列表后遍历
  servers:
  {% for s in SERVERS | split(pat=",") %}
    - {{ s | trim }}#{% if not loop.last %},{% endif %}
  {% endfor %}
  ```
- 变量与片段：
  ```tera
  {% set base = APP_NAME | lower %}
  fullname: {{ base }}-{{ APP_ENV }}
  {% include "DEFAULT_GROUP/fragment.yml" %}  # 路径使用 /，基于模板根目录
  ```
- 注释：`{# 这是注释，不会出现在结果中 #}`

提示：本项目使用 `Tera::default()` 注册模板，相对路径名即为模板名（包含子目录，统一使用 `/` 作为分隔符）。💡

## 兼容占位（${VAR}）语法
- 支持形式（变量名必须是 `A-Z0-9_`）：
  - `${VAR}`、`${ VAR }`
  - `${VAR:-default}`、`${ VAR : - default }`（建议不在默认值两侧加空格，避免意外空白）
- 转义：写 `$${VAR}` 将输出字面量 `${VAR}`（因为会先把 `$$` 还原为 `$`）。
- 缺失变量：
  - 默认严格模式：若有 `${MISSING}` 会报错并终止（可读中文错误）。🐛
  - 传入 `--allow-missing`：保留占位不替换（仍输出 `${MISSING}`），或使用默认 `${MISSING:-d}`。✅

工作顺序：先 Tera 渲染再处理 `${...}`，因此 `${...}` 只能读取“变量 YAML + 环境覆盖”得到的键；不能使用 `{% set %}` 在模板里定义给 `${...}` 使用的新键。⚠️

## 变量 YAML 写法（完整）

### 1) 扁平化与类型
- 层级键合并：`a.b.c -> A_B_C`（大小写转大写、层级用下划线 `_` 连接）。
- 值类型：
  - 字符串/数字/布尔：转换为字符串保存，例如 `8080 -> "8080"`、`true -> "true"`。
  - 数组/对象：序列化为 JSON 字符串，例如 `[1, 2] -> "[1,2]"`、`{x:1} -> "{\"x\":1}"`。
  - `null`：变成空字符串 `""`。
- 键名要求：只处理“字符串键”，建议使用不含破折号的 `snake_case/UPPER_SNAKE_CASE`，以便在 Tera 中直接使用。👍

示例（YAML -> 扁平变量）
```yaml
app:
  name: demo
  port: 8080
  flags: [a, b, c]
  extra: {x: 1, y: 2}
  empty: null
```
生成的键值（概念上）：
```
APP_NAME=demo
APP_PORT=8080
APP_FLAGS=["a","b","c"]
APP_EXTRA={"x":1,"y":2}
APP_EMPTY=
```

### 2) 文件合并与优先级（从低到高）
- 变量路径为“目录”：读取该目录下所有 `*.yml`/`*.yaml`，按“文件名升序”逐个合并，后者覆盖前者。📂
- 变量路径为“文件”：
  1. 先读取该文件；
  2. 再读取“同目录下同名 `.d/` 目录”里的所有 `*.yml`/`*.yaml`（升序）；
  3. `.d/` 内的值覆盖基础文件。🗂️
- 最后一步：环境变量对“已存在同名键”进行覆盖（只覆盖，不新增）。🌱

结构示例：
```
vars/dev.yaml
vars/dev.d/10-db.yaml
vars/dev.d/20-app.yaml
```
合并顺序：`dev.yaml -> 10-db.yaml -> 20-app.yaml -> 环境变量覆盖`

### 3) 环境变量覆盖
- 仅当某键已由 YAML 生成时，才会用同名环境变量（不区分大小写的本质等价，代码中会转大写）覆盖其值；不会凭空新增新键。
- 示例：
  - YAML 中已有 `APP_NAME=demo-app`；执行前设置 `APP_NAME=from_env`，最终为 `from_env`。
  - 若 YAML 中不存在 `FOO_BAR`，即使设置了同名环境变量也不会出现在渲染上下文中。

## 端到端示例
- 变量（`examples/vars.yaml`）
  ```yaml
  APP_NAME: demo-app
  APP_ENV: dev
  APP_URL: "http://127.0.0.1:8080"
  SERVERS: "a:8848,b:8848"
  ```
- 模板（`examples/template/DEFAULT_GROUP/app.yaml`）
  ```yaml
  ---
  dataId: app.yaml
  group: DEFAULT_GROUP
  ---
  app:
    name: "${APP_NAME:-demo}"
    env: "{{ APP_ENV | upper }}"
    url: "${APP_URL}"
    servers:
    {% for s in SERVERS | split(pat=",") %}
      - {{ s | trim }}
    {% endfor %}
  ```
- 渲染命令：
  ```bash
  nacos-tpl render -t examples/template -v examples/vars.yaml --print DEFAULT_GROUP/app.yaml --stdout
  ```

## 常见问题与排错 🐛
- “缺失变量”报错：未传 `--allow-missing` 且存在 `${MISSING}` 时会失败；补齐变量或使用默认 `${MISSING:-d}`。
- `${...}` 未替换：变量名需为 `A-Z0-9_`；或该键不存在于 YAML 扁平结果（环境变量不会新增）。
- include 路径：统一使用 `/` 分隔，路径相对于模板根目录（即 `-t` 指定目录）。
- 数组/对象：在变量中为 JSON 字符串，若需要结构化输出，建议在模板中使用 `json_encode` 结合目标格式处理。
